# 总控、角色与恢复

默认主窗口管理当前范围、状态和最终判断，将有明确输入/输出的独立任务交 subagent。分工不得违反宿主授权、并发限制或单 Agent 要求。不自动创建用户拥有的新窗口；只有用户明确要求才用窗口路线。无多 Agent 能力则顺序做并标“自审，非独立审核”。

按需要启动角色，不开常驻群：规划/覆盖读取目录与关系查遗漏；执行负责数据类或规格分片并独立输出；审核在候选、深化、文献三个阶段分别读证据，可以顺序启动。

分派只给任务、必需路径、输出位置、范围和验收，不传整段历史。审核尽量无历史，不喂预期系数或希望的结论；提供可访问原始证据，不只给执行摘要。角色分开不等于统计上独立错误。审核不覆盖被审产物，问题与复算另存；主窗口实读报告解决分歧，不能只凭“Agent 说通过”。

一套规格一个合并者，worker 独立分片。不要同时改源文件/台账。输入与完成结果不覆盖；代码/环境/选项变化则新版本。恢复先查进程是否活跃，不重复启动，更不能杀其他任务。

## 轻量持久状态

`START.md` 尽量 ≤1000 汉字：资产概况、实际完成情况、常用查询、关键不确定性和恢复入口。`run.json` 记范围、阶段、版本、环境、分片位置、状态计数、下一步和阻塞。不写长聊天日志/管理合同。

子任务返回 ≤1500 字摘要+路径+计数+已检查/未检查项。全量资产放磁盘，查询默认 ≤20 条并可选字段；大表不回灌主窗。候选/方法用 ID 引用结果，不重复复制成多份“发现”。

中断后核查指纹及完整性，跳过已验证完成规格，重试保留史。变化使相关结果 stale 并传递到候选、审核和文献支持。状态不全就修状态，不猜完成。无未使用样本/新颖候选是合法研究结果。

## 交付

检查路径、一一对应、全量结果、哈希、字典抽查、命令、关键估计/量级复算、多重检验和文献状态。新 Agent 只拿 Skill、START、run 应可查到数据、做法、完整结果、争议及文献，无需旧对话。明确功能试验和研究结论，哪些方法尚未实测。Skill 不是后台服务，不保证应用关闭后持续运行。
